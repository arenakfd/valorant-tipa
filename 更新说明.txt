────────────────────────────────────────────────
一、这一版怎么来的：把成品内核那条链逐指令重建出来
────────────────────────────────────────────────

不是"参考"，是把它的主循环（反汇编 0x1000901e0 ~ 0x100093200 这一段）
一条一条读出来，按它的顺序、它的偏移、它的比较方式原样搬。

它每帧现扫 Actor 全表，对每个 Actor 依次过 5 道门，全在一条链上：

  门①  0x1000909e4   Actor 空指针                       → 跳过
  门②  0x100090a4c   目标 Actor == 自己 Pawn（全局缓存）  → 跳过
  门③  0x100090a70   read32f(目标 + 0x4CC) != 40.0f      → 跳过   ← 人形门
  门④  0x100090ad0   目标 Actor == 自己 Pawn（它查第二遍）→ 跳过
  门⑤  0x100090ae8   目标 PS = read64(目标 + 0x3D8)
        0x100090bec     w24 = read32(目标PS + 0x648)
        0x100090b5c     x21 = read64(自己Pawn + 0x3D8)
        0x100090c48     w8  = read32(自己PS + 0x648)
        0x100090cc0     cmp w24, w8  相等 → 跳过（同队）
        0x100090ccc     目标PS == 自己PS        → 跳过（自己）
        （目标 PS == 0 时整段跳过：人机不参与队伍判定）
  门⑥  0x100090cdc   死亡组件 0x18E8 → +0x1F8 位0 = 1     → 跳过

这 5 道门，就是它"不漏人、也不画队友"的全部原因。

────────────────────────────────────────────────
二、真人 / 人机 —— 它只用了一个比较，我们照搬那一个
────────────────────────────────────────────────

我们以前是用好几层判据推（类型字段、类继承链、类名），层层之间会打架。
成品内核根本不推，它是这样（反汇编 0x100090d98 ~ 0x100090dc4）：

    x8 = [目标的 PlayerState]
    cmp x8, 0
    csel 计数槽          ; PS != 0 → 计数器 A，PS == 0 → 计数器 B
    计数器 += 1

计数器 A、B 就是它顶部那行计数（字符串常量逐字节解出来是 玩家%d / 人机%d，
显示点在 0x100092f5c / 0x100093000）。也就是说：

    PlayerState != 0  →  真人
    PlayerState == 0  →  人机

它**不读** PlayerStateType(0x5F4)，**不读** CachedCharacterType(0x1679)，
也不看类名。我们这一版把自研的那几条全删了，只留这一个比较。

为什么这一条重要：
    旧版在"人机显示"关掉时，靠自研判据决定谁是人机 —— 只要一个真人被判成
    人机，他就不画了（就是你看到的"漏真人"）。现在判据本身跟成品一致，
    这条路直接消失；同时顶部"附近 真人 X 人机 Y"也跟成品同口径。


────────────────────────────────────────────────
三、队友过滤 —— r38 那次换错在哪，这次换回什么
────────────────────────────────────────────────

r38 把判据换成了 ASGTeamInfo 指针相等（自己PS→TeamComponent→Team ↔ 目标同链），
理由是"指针比较不解释数值"。它错过了一个前提：

    独狼（solo）玩家在游戏里没有真实小队 —— Team 要么是空指针，
    要么指向同一个"无队伍"的默认对象。

于是同局两个互不相干的独狼，指针彼此相等 → 被判成队友 → 剔掉。
"全灭保险"只挡得住"整轮全剔"，挡不住"一部分真人被剔" —— 表现就是漏真人。

这一版换回成品内核那一条（就是上面门⑤）：

    自己PS(自己Pawn + 0x3D8) + 0x648 读 int32  ==  目标PS + 0x648 读 int32  → 同队

dump 1.0.249 实证：
    0x3D8 = APawn::PlayerState
    0x648 = ASGPlayerState::TeamIndex (int32，旁边就是 TeamName/TeamLogo，是战队信息块)
    0x692 = ASGPlayerState::TeamType  ← 阵营是这一个（PMC/SCAV），r38 认错的是它

所以判的是"游戏自己发的队伍编号"：独狼各有各的号，不会撞车。
自身判据两条一起上：目标 Actor == 自己 Pawn（它查两遍，我们也两遍）
或 目标 PS == 自己 PS。


────────────────────────────────────────────────
四、删掉的自研判据（清单，方便你对照旧版）
────────────────────────────────────────────────

  ① PlayerStateType(0x5F4) 一票定性 —— 成品没用，删
  ② CachedCharacterType(0x1679) —— 成品没用，删
  ③ "SGAICharacter 继承链" / 类名含 AICharacter·UamAI —— 成品没用，删
  ④ r38 的 TeamInfo 指针相等 + SquadIndex 兜底 —— 会误剔独狼，删
     （0x590/0xE8/0x680 三个偏移只在 SDK.h 留档，不参与任何判定）

保留的只有一处，而且它只会"多画"，永远不会"少画"：

    队友全灭保险 —— 一轮里所有人**都**被判成队友时，判定判据悬空
    （换局残影 / 读串），全部放行，绝不给你空屏。


────────────────────────────────────────────────
五、上机怎么验（不用猜，看数字）
────────────────────────────────────────────────

诊断行里这一段是给这一版做验证用的：

    队: 自身PS√ 队号X(小队Y)

  ① 自身PS 后面是 √ —— 基准值拿到了，队友过滤真的在工作
     （显示 × 时本轮不做队友过滤，只会多画，不会误剔）
  ② 队号 X 应该跟队友一样、跟敌人不一样 —— 组排时数一下就知道判据对不对
  ③ 真人数量：人机开关关掉（只画真人）后，顶部"真人"数应该跟实际人数对上；
     旧版这里是靠自研判据推的，人会越推越少

  ④ 如果还漏人：看"截"是不是大于 0（名额问题，不是判据问题），
     或者名单里那个人 自身PS 是 ×（基准值那一刻没读到）。


────────────────────────────────────────────────
六、诚实的边界
────────────────────────────────────────────────

· 门③ 是成品内核的"人形判据"：read32f(目标+0x4CC) 必须正好 40.0f。
  它是 ACharacter::CrouchedEyeHeight 的默认值（dump 实证在 0x4CC）。
  我们这边**没有**把它当成唯一门槛 —— 类继承链那条仍然并着走（取并集），
  两条任意一条过就收。理由是：这一条只会让"收得多"，拆掉它不会让漏人变少，
  反而会多一条漏法。成品核心里它用的是单条，这点差异在这写清楚。
· 死亡那一门（0x18E8 → +0x1F8 位0）跟成品等价，但我们是按类名扫组件缓存表
  找到同一个组件再读同一个字段（抗游戏更新漂移），不是硬写槽号 2。
· 唯一保留的护栏是"队友全灭放行"，理由上面写了：它只会多画。
